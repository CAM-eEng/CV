# Bot PAT Implementation Plan

> **For agentic workers:** This is a small focused plan (6 tasks). Use superpowers:subagent-driven-development or executing-plans if you want the per-task dispatch + review pattern, or just execute inline — it's short. Steps use `- [ ]` checkboxes.

**Goal:** Eliminate the manual-merge step from the nightly activity refresh chain by swapping `GITHUB_TOKEN` for a dedicated fine-grained PAT in `refresh-activity.yml`. End state: cron fires → PR created → CI runs → auto-merge fires → deploy dispatches → site updates. No human in the loop.

**Architecture:** Add one repo secret (`BOT_PAT`), a fine-grained PAT scoped to `CAM-eEng/CV` with `contents: write` + `pull_requests: write` permissions. The PR-create + auto-merge + workflow-dispatch steps in `refresh-activity.yml` switch to that token. GitHub's anti-recursion guard treats PAT-attributed pushes as "real" pushes, so CI fires on the bot PR, auto-merge proceeds normally, and the deploy chain closes itself.

**Reference docs:**
- The problem this fixes: `READ-BEFORE-BURNING.md` § "Before you write a GitHub Actions workflow" (now expanded with this caveat in Task 5).
- Plan 3 ledger: `docs/superpowers/plans/2026-05-11-cv-activity-visualizer.md` (the workflow being modified was shipped there).

## Task 3: Swap GITHUB_TOKEN → BOT_PAT in refresh-activity.yml

**Files:**
- Modify: `.github/workflows/refresh-activity.yml`

Three call sites need the new token. The "Refresh activity" step keeps `GITHUB_TOKEN` because it doesn't push anything — it only reads.

- [ ] **Step 1:** Edit `.github/workflows/refresh-activity.yml`. Find the `Open / update PR if changed` step and change:

  ```diff
        - name: Open / update PR if changed
          id: open-pr
          uses: peter-evans/create-pull-request@67ccf781d68cd99b580ae25a5c18a1cc84ffff1f # v7.0.5
          with:
  -         token: ${{ secrets.GITHUB_TOKEN }}
  +         token: ${{ secrets.BOT_PAT }}
            commit-message: 'chore(activity): nightly refresh'
  ```

- [ ] **Step 2:** Find the `Enable auto-merge on the PR` step and change:

  ```diff
        - name: Enable auto-merge on the PR
          if: steps.open-pr.outputs.pull-request-number != ''
          env:
  -         GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  +         GH_TOKEN: ${{ secrets.BOT_PAT }}
          run: gh pr merge ${{ steps.open-pr.outputs.pull-request-number }} --squash --auto --delete-branch
  ```

- [ ] **Step 3:** Find the `Wait for merge, then dispatch deploy` step and change:

  ```diff
        - name: Wait for merge, then dispatch deploy
          if: steps.open-pr.outputs.pull-request-number != ''
          env:
  -         GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  +         GH_TOKEN: ${{ secrets.BOT_PAT }}
          run: |
  ```

  (Same env var, different secret. The script body stays the same.)

- [ ] **Step 4:** Remove the now-unused `permissions:` block? **No** — leave it. With a PAT, the workflow's `permissions:` block is irrelevant for the steps using `BOT_PAT`, but the `Refresh activity` step still relies on `GITHUB_TOKEN` for the implicit Git config done by `actions/checkout`. Removing `permissions:` could break that. Keep:

  ```yaml
  permissions:
    contents: write
    pull-requests: write
    actions: write
  ```

  (Slightly over-permissioned but harmless and reverts to PAT scope where it matters.)

- [ ] **Step 5:** Verify locally:

  ```bash

  ```

  Then commit on a feature branch:

  ```bash

  git commit -m "$(cat <<'EOF'
  ```

- [ ] **Step 1:** Open `READ-BEFORE-BURNING.md`, find the "Before you rotate a PAT" section. Add a paragraph after the existing rotation cadence:

  ```markdown
  Three PATs to rotate now, each on its own 90-day cycle:

  - `GH_API_TOKEN` — fine-grained, read-only on public data. Used by the activity-refresh script to call the GitHub REST + GraphQL APIs. Lower-impact if leaked.
  - `HTB_API_TOKEN` — opaque HackTheBox JWT. Lower-impact if leaked (no write scope on anything you'd care about).
  - `BOT_PAT` — fine-grained, repo-scoped to `CAM-eEng/CV`, with `contents: write` + `pull_requests: write` + `actions: write`. **Highest-impact of the three** if leaked; an attacker could push to main (subject to branch protection), open PRs, dispatch workflows. Rotate on the same cadence; do NOT extend; revoke the old one immediately after swapping.
  ```

## Task 6: End-to-end verification

**Files:** none (smoke test only).

This is the gate: trigger the workflow manually and confirm the full chain fires without any human intervention.

- [ ] **Step 1:** From `main`, trigger refresh-activity:

  ```bash
  gh workflow run refresh-activity.yml
  gh run watch
  ```

- [ ] **Step 2:** Within ~5 minutes of the run completing successfully, **a fresh refresh PR should auto-merge and a deploy should fire** without you clicking anything. To verify:

  ```bash
  # The refresh PR should be MERGED, not OPEN:
  gh pr list --search "chore(activity)" --state all --limit 2

  # A deploy.yml run dispatched after the merge:
  gh run list --workflow=deploy.yml --limit=2
  ```

- [ ] **Step 3:** Verify the deploy succeeded and the homepage shows fresh data:

  ```bash
  # generatedAt timestamp should be recent (within last hour):
  curl -sf https://cameronhartman.dev/cv.json >/dev/null  # quick reachability check
  curl -sf https://cameronhartman.dev/ | grep -oE "refreshed [A-Za-z]+ [0-9]+, [0-9]+"
  ```

- [ ] **Step 4:** If the chain breaks anywhere:
  - Check that PR's CI ran (it should have, with the PAT). If it didn't, `BOT_PAT` scope is wrong — re-do Task 1 with the listed scopes.
  - Check the workflow log for the `Wait for merge, then dispatch deploy` step — it'll tell you exactly what state the PR ended up in.
  - As an emergency manual override, `gh workflow run deploy.yml --ref main` always works.

Open question for future-you: **GitHub Apps would be cleaner than a PAT.** A repo-scoped GitHub App can authenticate via short-lived installation tokens (no manual rotation), use `actions/create-github-app-token` to mint tokens in workflows, and have audit trails distinct from your user account. If you're going to maintain this site for years, the App route avoids the 90-day rotation chore. Estimated cost: one afternoon to set up the App + swap `BOT_PAT` for `APP_PRIVATE_KEY` + `APP_ID`. Out of scope here; mentioning so you know the next door.
